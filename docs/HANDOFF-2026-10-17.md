### 4.4 最新一轮：工作动作与食物流转

- `src/workflow.js` 为一次玩家指令生成内部步骤；原有的切配、上锅、装盘、送餐、收款、清洁点击方式保留。
- 切配：`fetch → lay → chop → stow`，抽屉取料、放砧板、扶料持刀切配、收好备料盘。
- 上锅：`pickup → pour`，从对应备料位置端起、搬运、抬盘倾倒到对应炉位。
- 装盘：`scoop / pickup → garnish`，从锅中盛出或取组合原料、搬到出餐位置、摆盘调味。
- 送餐：`lift → deliver`，端起成品、沿通道移动，到桌边后放下。修正过“仍在送餐途中，餐点却已经显示在桌上”的问题。
- 外带餐使用纸袋形态，交给顾客后随顾客移动至离店。
- 接待有招手、记单、指路；收款有接过和收妥餐费；清洁有擦桌、将餐具收进手里、端往水槽、清洗。
- 对应道具包括刀、汤勺、锅铲、托盘、空碗、调味瓶、记单本/笔、纸钞、抹布、叠盘和清洗水滴。
- 汤锅和浅煎盘按制作方式切换；调整了切刀握持与高度、擦桌及放餐高度。
- 每份订单复用一个食物对象，切换 raw / chopped / cooking / plated / packed 形态；运输阶段跟随持物锚点。
- 工作计划、动作进度、食物位置、携带者入存档；原料在取料时扣一次，读档不重复扣料。
- 熟食在盛出前仍占炉位；废弃料理会释放炉位和携带者，避免永久占用。
- 完成事件在整次状态转移和携带清理完成后再通知 UI，防止自动存档捕获“送达但未用餐”或“已收钱但未离店”的半完成状态。
- 新增内部动作分摊原动作时间；基础工作移动速度从 2.8 调到 3.8，补偿新增加的搬运路程。不能把这个速度单独改回去而不复测经营难度。

必须保持的关系：

1. 订单外层阶段 `new → preparing → needsHeat → heating → needsPlate → ready → carrying → served` 与内部任务步骤是两套状态；组合装盘可跳过加热。不要只改一层而让渲染和逻辑脱节。
2. `job.location / job.visual / job.carrier / actor.carriedJob / task.plan / task.stepIndex / task.step / task.phase / task.progress / task.stockTaken` 要一致，并可序列化恢复。
3. 食物在 `location='actor'` 的行走阶段必须跟随该角色的 `carry` 锚点。不要在 `deliver` 尚处于 `walk` 时提前放到桌面。
4. 成熟料理在锅中等待盛出时仍占炉位；取出才释放。废弃料理不能留下炉位占用。
5. `Engine.complete()` 的完成通知要在状态清理后发出，因为 UI 的通知回调会同步保存。
6. `TABLE_SURFACE_Y` 和持碗锚点/手臂求解有关联；碗和筷子均有避开桌面的几何测试，不要仅凭截图任意降低碗的位置。
7. 门口边界在 `GUEST_ENTRY` 中，顾客排队/入座/离店必须维护门洞通行。不要将一般最短路直接替换掉强制入口路径。
8. 用户的既有档案需要迁移兼容，不清空现金、订单、库存或教学完成记录来掩盖问题。
9. 引导箭头应保留 DOM 节点，只改变位置；反复设为 hidden 再显示可能重启动画，导致上下浮动几乎看不到。
10. 暂停、后台和竖屏要冻结营业与场景时间；减少动效不能删除必要的工作状态反馈。
